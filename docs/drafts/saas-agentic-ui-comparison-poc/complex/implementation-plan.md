# 复杂 SaaS Agentic UI 实验计划

## 研究问题

对已有客户、工单、报价 GUI 和 API、但没有助手的 React SaaS，比较 DSH 原生 UI、assistant-ui 和 CopilotKit 接入相同业务流程的能力与额外协调成本。业务组件、权限、幂等和版本控制保持一致，允许各路线使用自己的原生交互设施，不强制共用聊天交互状态机。

主实验先验证 CopilotKit 的原生工具、人工介入及页面上下文是否真正参与业务闭环，再与 assistant-ui 在同一复杂故事中比较额外协调成本；不是把“功能可实现”误写成“框架成本更低”。保留已有两个 PoC 和第一轮实验的功能；DSH 原生 UI 保留 scripted 对照，不为追求三路线等量真实模型而扩大范围。

## 场景与验收

| 场景 | 操作与故障 | 成功凭据 |
|---|---|---|
| 跨页面上下文 | 选择工单、批量分配、切客户与报价页、撤销旧能力 | DSH 请求工具列表与已记录页面读取结果；不存在跨客户误操作 |
| 协同编辑 | 人工修改预算，Agent 修改折扣，旧版本提交 | 保留人工字段；冲突拒绝而非覆盖；GUI 与聊天复用编辑组件 |
| 多阶段审批 | 编辑报价、批准或拒绝、确认发送 | DSH 问答服务收到答案；同一调用与 turn 续跑；审批版本与发送版本匹配 |
| 生命周期 | 等待时停止、晚到答案、失败后继续、刷新 | 无遗留等待者、无重复用户输入、历史不重放副作用 |
| API 安全 | 只读角色、重复 operation id、响应丢失重试 | 服务端拒绝与稳定 receipt；无额外业务写入 |

## 实施顺序

1. 验证分段 AG-UI run：DSH 等待原工具时结束观察段，由 CopilotKit 原生 handler/respond 执行，再把原 call id 的结果交回同一个 DSH turn；记录这层适配的新增维护责任。
2. 实现有客户隔离、版本与 receipt 的 mock API，以及可独立操作的 SaaS 页面。
3. assistant-ui 与 CopilotKit 接入相同业务故事；CopilotKit 使用原生前端工具与 HITL，assistant-ui 使用 External Store/ToolCall 适配；DSH 原生 UI 保留已完成的 scripted 对照。
4. 单测、scripted 浏览器故障矩阵与真实模型多轮验收，记录网络、Session、业务 receipt 和截图。
5. 更新导读、手动验收、实验结论，明确未验证项。

## 第三轮：多模块边际成本验证

在已有工单、报价和跨客户续约模块之外新增账单争议减免模块，保持同一 DSH Worker、Session、默认 Agent Loop、业务 API 约束和共享 React 组件策略。账单流程必须包含页面读取、可编辑人工审核、批准后同一 turn 续接和版本/幂等校验。

1. 不修改既有 DSH 适配器，验证新增模块是否只需要增加页面能力、业务命令、共享卡片和框架级注册。
2. 对 assistant-ui 与 CopilotKit 执行同一账单故事，断言原始 call id、DSH turn、工具结果、业务 receipt 和同源网络。
3. 用 scripted、真实 Chrome 和 Playwright WebKit 运行矩阵；WebKit 只作为浏览器引擎证据，不宣称 Safari.app 通过。
4. 记录真实模型非确定性失败，不用放宽断言或额外用户 prompt 把失败改成成功；修正测试用例语义后重新验收。
5. 根据三个业务模块的固定与增量责任更新路线判断；不把“适配器可复用”直接等同于“总成本更低”。

## 约束

不修改 DSH Agent Loop，不建立第二份模型历史，不把协议续接当成新 prompt。凭据只由 backend 从主工作区 `docs/drafts/.env` 读取。独立 worktree 与分支保留原实验。页面关闭终止 Worker，不承诺恢复执行中的人工等待。生产 Provider 注入尚未解决时如实标记，不为通过实验切换模型循环。

## 第二轮：相同复杂交互的成本比较

在主工作区 `research` 上继续，不创建 worktree。assistant-ui 与 CopilotKit 同时实现跨客户批量续约：复用两个报价编辑器、保留人工修改、原始调用审批、原子提交、并发版本冲突、拒绝、停止、刷新及已提交结果重放。原生路线只保留回归，不扩展攻坚。

1. 修复验收器的无状态长等待，按原始调用、Session 结果和 turn 终止判断下一步；保留真实模型失败，不用额外 prompt 掩盖同 turn 续接失败。
2. 将人工批准的内容和身份绑定到服务端业务凭据；没有批准、改参数、拒绝或撤销后不能提交，不能依靠工具说明提供权限保证。
3. 对相同输入和故障点执行 Chrome 与 Playwright WebKit scripted/真实模型测试，检查模型请求、唯一工具结果、业务副作用和恢复。
4. 记录共同业务成本、框架专属实现/测试、复用的 adapter、运行与生产化限制；新增场景的增量与既有初始投入分开统计。
5. 给出本次固定版本、DSH 唯一执行者约束下的成本选择与适用条件，不把代码行数等同于工时或承诺所有未来场景的终身成本。
